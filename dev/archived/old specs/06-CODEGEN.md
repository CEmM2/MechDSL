# 06 — Code Generation

## 1  Printer architecture

Each backend is a SymPy-style **printer**: a class that walks the symbolic expression tree from SymPDE's `TerminalExpr` and emits target-language source code. The printer also generates solver scaffolding (mesh I/O, time stepping, BC application).

```python
class BasePrinter:
    """Abstract code generator."""

    def generate(self, wf: WeakFormResult, ctx: dict) -> str:
        """Return complete source code for the solver."""
        sections = [
            self.emit_header(ctx),
            self.emit_data_structures(ctx),
            self.emit_constitutive(ctx),
            self.emit_element_kernel(wf, ctx),
            self.emit_assembly(wf, ctx),
            self.emit_solver(ctx),
            self.emit_boundary_conditions(ctx),
            self.emit_postprocess(ctx),
            self.emit_main(ctx),
        ]
        return '\n\n'.join(sections)
```

Each `emit_*` method is overridden by backend-specific printers.

### 2.2  Expression-to-kernel mapping

The printer walks the `TerminalExpr` tree and maps SymPDE operators to Taichi code:

| SymPDE expression | Taichi code |
|-------------------|-------------|
| `dx1(u[0])` | `dN_dX[a, 0] * u_local[a][0]` (summed over `a`) |
| `dx2(u[1])` | `dN_dX[a, 1] * u_local[a][1]` |
| `u[0] * v[0]` | mass matrix contribution |
| `Constant('rho')` | `rho_val` (substituted at code gen time or kept as parameter) |

The printer maintains a symbol table mapping SymPDE's abstract symbols to Taichi field accessors.

### 2.3  Performance considerations

**Element stiffness storage:** For implicit solvers, avoid storing full 6×6 `ti.Matrix` fields (triggers Taichi unrolling warnings for matrices > 32 entries). Instead, store the constitutive tangent as flat `ti.field` arrays and compute element stiffness on-the-fly.

**Atomics:** Internal force scatter uses `ti.atomic_add`. For large meshes, consider element colouring to avoid atomics.

**Shape function gradients:** Precompute reference-element shape function gradients and quadrature weights in `ti.static` tables. Transform to physical gradients per element using the Jacobian.

**Block size:** Use `ti.loop_config(block_dim=128)` for the element kernel.

### 2.4  Explicit dynamics variant

For explicit time integration (central difference):

```python
@ti.kernel
def explicit_step(dt: ti.f64):
    for i in range(n_nodes[None]):
        if not bc_mask[i]:
            a = (f_ext[i] - f_int[i]) / mass_lumped[i]
            v[i] += a * dt
            u[i] += v[i] * dt
```

The code generator switches between implicit (Newton-CG) and explicit (central difference) based on the `% mechanics solver` directive.

### 3.2  MFEM-specific considerations

- MFEM uses **engineering Voigt** convention for some built-in integrators. The printer must insert shear scaling factors when interfacing with MFEM's internal stress representations.
- MFEM's mesh, function space, and solver setup is boilerplate. The printer generates it from the context dictionary.
- MFEM natively supports MPI parallelism. The generated code should use `ParFiniteElementSpace` and `ParNonlinearForm`.
- MFEM supports its own AD via `ceed` for matrix-free operators. The printer can target this for high-performance kernels.

## 5  Common code generation utilities

### 5.1  Shape function libraries

The code generator includes precomputed shape function data for supported elements. These are target-independent and stored as numpy arrays:

```python
# CST (Tri3)
N_tri3 = [lambda xi, eta: 1 - xi - eta,
          lambda xi, eta: xi,
          lambda xi, eta: eta]
dN_tri3 = [[-1, -1], [1, 0], [0, 1]]  # constant gradients
quad_tri3 = [(1/3, 1/3, 1/2)]  # single point, weight = area

# Q4 (Quad4)
N_q4 = [lambda xi, eta: (1-xi)*(1-eta)/4, ...]
# etc.
```

### 5.2  Einsum-driven kernel emission

Before emitting element kernels, the printer calls the einsum optimiser (see `09-EINSUM-OPTIMISER.md`) to obtain a `ContractionPlan`. The plan dictates the emission strategy per contraction step:

- **Tier 1 steps** emit calls to pre-written Taichi library functions (e.g. `pk1_from_pk2(F, S)` which wraps `F @ S`).
- **Tier 2 steps** emit inline `ti.static` loop nests. The emitter walks the step's einsum string and generates the index arithmetic, intermediate allocation, and accumulation code. All physics indices are unrolled; all mesh indices are runtime loops.
- **Tier 3 steps** (rare, only for exotic contractions) emit runtime loops for the outer indices and `ti.static` for the innermost contracted dimension only.

The JIT budget counter validates the total unrolled line count before any Taichi source is written. If the budget is exceeded, the emitter restructures into multiple `@ti.func` sub-functions to stay within the per-function limit.

### 5.3  Expression simplification

Before emitting code, the printer runs SymPy `cse()` (common subexpression elimination) on the constitutive expressions. This can reduce operation count by 30-60% for complex tangent expressions.

```python
from sympy import cse

replacements, reduced = cse(tangent_expressions)
# replacements: [(x0, expr0), (x1, expr1), ...]
# reduced: simplified expressions using x0, x1, ...
```

The printer emits the replacements as local variables and the reduced expressions as the final computation.

### 5.3  Numerical safeguards

Generated code includes:

- `J > 0` check (element inversion detection)
- `det(F) > tol` before computing `F^{-1}`
- `σ_eq > tol` before computing flow direction `n = s/||s||`
- Plastic multiplier `Δλ ≥ 0` assertion
- Damage `D ∈ [0, 1)` clamping

See `07-CONVENTIONS.md §6` for the exact tolerance values.
