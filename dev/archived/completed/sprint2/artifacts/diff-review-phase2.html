1 — Executive Summary

From Cartesian to Curvilinear

This branch extends MechDSL's symbolic engine from Cartesian-only tensor mechanics to a full convected coordinate framework. Where previously all quantities assumed G = I (flat space), the compiler now supports arbitrary curvilinear reference configurations with position-dependent metric tensors GIJ(θ), Christoffel symbols, and covariant derivatives — the mathematical infrastructure needed for problems on curved domains (cylindrical shells, annular meshes, fiber-reinforced composites).

Along the way, the branch also completes Phase 1 (Updated Lagrangian formulation) with tangent operator emission, formulation switching, and TL/UL equivalence verification. The critical finding: Gate B review caught a genuine physics bug in the convected metric formula (FTGF vs GTCG) — the kind of error that tests with isotropic deformations would never reveal.

10 — Decision Log

G_ref_vecs (base vectors), not G_metric (metric tensor)

Rationale: The formula gIJ = GT C G requires reference base vectors GI, not the metric tensor GIJ. The original API took G (metric) and computed F^T @ G @ F, which is wrong when F is the Cartesian deformation gradient. Caught by Gate B domain review during P2-1.

Alternative: Could keep the metric API and transform internally, but this adds an unnecessary square root decomposition step.

Confidence: High — sourced from gate review and independent derivation

gamma[K,I,J] = ΓKIJ index convention

Rationale: First upper index = raised index. Consistent with NRPyLaTeX gammaUDD convention and standard textbook notation. All three covariant derivative functions use this consistently.

Confidence: High — documented in code, verified in 4 unit tests

P2-5 tests at constitutive level, not full FEM solve

Rationale: The element assembly pipeline doesn't support curvilinear meshes yet — that's downstream codegen work (Phase 5+). Plan spec B2.5 says "exact stress" and "identical results within 1e-12", achievable at the constitutive level. Full pipeline curvilinear verification is P10-1.

Alternative: Build a minimal curvilinear solver for testing only. Rejected: scope creep, solver work belongs in later phases.

Confidence: High — discussed in Gate A/B review, plan spec referenced

UL fold-over detection via poison residual (1e300)

Rationale: Instead of silently skipping degenerate elements (detj ≤ 0), the residual is poisoned with 1e300 so the Newton solver detects the fold-over via divergence. This prevents converging to a wrong solution with inverted elements.

Confidence: Medium — inferred from code, standard practice in nonlinear FEM

Truesdell rate for UL tangent (not Jaumann)

Rationale: Changed from Jaumann+Hadamard to Truesdell+standard geometric stiffness after P1-5 follow-up. Truesdell rate is work-conjugate to the Kirchhoff stress and produces the correct consistent tangent for Newton convergence.

Alternative: Jaumann rate with Hadamard correction. Rejected: produces asymmetric tangent contributions that complicate the implementation without benefit.

Confidence: High — sourced from commit ee6185c, verified by TL/UL equivalence test
11 — Re-entry Context
Key invariants, coupling, gotchas

Key Invariants

  • ◆ compute_convected_metric expects base vectors (G_ref_vecs), not the metric tensor. Passing the metric tensor silently produces wrong results for non-isotropic F.
  • ◆ Index convention: gamma[K,I,J] = ΓKIJ. All covariant derivative functions rely on this. Swapping indices produces subtly wrong results that pass symmetry tests but fail physics tests.
  • ◆ The christoffel_symbols fast-path returns zeros when the metric has no coordinate dependence. This is correct but means passing a constant (non-identity) metric still returns zeros.

Non-obvious Coupling

  • ◆ parser.py lines propagating metric_current/metric_reference to context dict — only 2 lines, but if removed, the _mech_assign handler in directives.py stores values that never reach downstream.
  • ◆ objective_rates.py::truesdell_tangent is imported inside the UL golden file generated_ul_svk.py.golden at runtime — renaming/moving it breaks the golden test without a direct import chain.
