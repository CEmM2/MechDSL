Sprint 3 Phase 2: Cook's Membrane Benchmark

sprint3_phase-1 → sprint3_phase-2 · 4 commits · 12 files

Phase 2 turns a placeholder rectangular mesh into a proper Cook's membrane benchmark with trapezoidal geometry and J2 plasticity. The core insight: detect boundary tags before coordinate warping, because the y1 face is no longer at a constant y-coordinate after the trapezoidal transformation. This single ordering decision -- tag detection before warping -- makes the entire mesh generator correct without any post-hoc fixups.

The pure-NumPy reference solver caps out at ~50 nodes, forcing a pragmatic compromise: 2x2x1 mesh (18 nodes) instead of the plan's 8x8x1 (162 nodes). The benchmark validates solver reproducibility rather than mesh convergence -- an honest tradeoff that's fully documented.

Decision Log

Pre-warp boundary tag detection for trapezoidal meshes
High -- from plan context
Rationale
After warping, the y1 face has varying y-coordinates (from 44 at x=0 to 16 at x=48). Detecting tags on the rectangular mesh before warping means y1 is simply "all nodes at y=Ly", which is trivial and exact.
Alternatives
Post-warp detection using the original j-index from the structured grid. Rejected: requires tracking node metadata through the warp, more complex for no benefit.
2x2x1 mesh instead of plan's 8x8x1 for production test
High -- documented in Phase 1 handoff
Rationale
The pure-NumPy CG reference solver scales as O(N^5/3) and is computationally infeasible beyond ~50 nodes. An 8x8x1 mesh has 162 nodes -- 3x the ceiling. A 2x2x1 mesh (18 nodes) runs in ~90 seconds.
Alternatives
Use scipy.sparse.linalg.cg (not available -- scipy not in deps). Implement a preconditioned solver (out of MVP scope). Wait for Taichi backend (generates code, different test path).
nu=0.3 instead of literature's nu=0.4999
High -- from sprint3 plan
Rationale
Standard Hex8 elements exhibit volumetric locking at nu approaching 0.5. B-bar/F-bar formulations that fix this are out of MVP scope. Using nu=0.3 avoids locking while still testing the J2 plasticity code path.
Alternatives
Implement B-bar (rejected: scope creep). Use reduced integration (rejected: hourglass control needed). Accept locking artifacts (rejected: non-physical results).
Self-converged reference instead of literature digitization
High -- from sprint3 plan
Rationale
With nu=0.3 (not 0.4999), results won't match published literature values anyway. A self-converged reference from the same solver validates reproducibility without requiring literature digitization infrastructure.
Alternatives
Digitize de Souza Neto (2008) figures (rejected: nu mismatch makes comparison meaningless). Use analytical solution (doesn't exist for Cook's membrane).
Newton tolerance relaxed to 1e-6 from convention's 1e-8
Medium -- inferred from code comment
Rationale
The unpreconditioned CG solver on coarse meshes requires more iterations to reach tight tolerance. Relaxing to 1e-6 keeps the solve tractable while still ensuring physical accuracy (residual drops 6 orders of magnitude).
Alternatives
Use 1e-8 with higher cg_max_iter (would increase solve time significantly). Accept possible CG stagnation.
Re-entry Context (note to future self)

Key Invariants

  • generate_cook_membrane_mesh MUST detect boundary tags before warping y-coordinates. If the warp line moves above the tag detection, y1 tags will be wrong.
  • The warping formula y' = y * (44 - 28x/48) / 44 assumes the pre-warp mesh spans exactly [0,48] x [0,44] x [0,1]. Changing Lx/Ly/Lz requires updating the formula.
  • _REFERENCE_TIP_UY = 4.6999070649 is valid ONLY for: 2x2x1 mesh, total_shear=100N, 10 steps, tol=1e-6, cg_max_iter=2000. Changing any parameter invalidates it.

Non-obvious Coupling

  • generate_cook_membrane_mesh is reused by P5-2 (example scripts) -- API changes affect downstream.
  • TestCooksMembrane's class-scoped fixture means test ordering within the class matters -- if any test mutates u in place, all subsequent tests see corrupted data.

Gotchas

  • The Cook's membrane material stays elastic at these load levels (E/sigma_y0 ~ 1.0, yield strain ~100%). To actually exercise plastic deformation, either increase the total shear force significantly or reduce sigma_y0.
  • The reference generation script (_gen_cooks_ref.py) is prefixed with _ so pytest won't collect it. If renamed, it will be discovered as a test file and its test_cooks_4x4 will run in CI (slow, prints to stdout).

Don't Forget

  • Phase 3 (necking bar) will hit the same solver performance ceiling. Plan for 2x2x4 or similar coarse meshes, not the plan's 4x4x16.
  • When a faster solver arrives, regenerate Cook's reference on 8x8x1+ mesh and update _REFERENCE_TIP_UY.
  • The connectivity loop duplication (mesh_io.py) should be refactored if Phase 3 adds a third mesh generator.
