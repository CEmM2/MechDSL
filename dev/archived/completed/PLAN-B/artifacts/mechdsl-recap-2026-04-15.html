01 · Project Identity
Elevator Pitch

MechDSL is a compiler that bridges physics notation and GPU simulation code. You describe a solid mechanics problem in LaTeX tensor notation (or programmatically), and the pipeline emits deterministic, ready-to-run Taichi solver kernels — no hand-coding finite elements, no manual index gymnastics.

The MVP covers 3D Hex8 Total Lagrangian solid mechanics with SVK elasticity and J2 power-law plasticity. A second package, algo2code, transpiles LaTeX algorithm pseudocode (PCG solver) into the same Taichi target.

Stage: MVP complete and tagged v0.1.0. All Sprint 3 exit criteria verified. Post-MVP Plan B work (Updated Lagrangian, hyperelastics, additional elements) is designed but not yet started.

Who uses it: Single researcher/developer (SOSOVSKI) building the system bottom-up, with agent-driven sprint execution. No external users yet.

Packages
  • mechdsl-core
    LaTeX tensor expressions → FEM solver code (Taichi). 6-layer compiler pipeline. SVK + J2 plasticity.
  • algo2code
    LaTeX algpseudocode → executable Taichi. Zero runtime deps. PCG transpilation for Newton driver.

04 · Decision Log
D-1 Finite-difference J2 tangent in MVP; analytical tangent deferred to Plan B
What: The emitted J2 plasticity kernel uses a finite-difference consistent tangent (taichi_printer.py:517–520).
Why: Analytical consistent tangent crosses codegen, solver, and verification layers simultaneously — out of MVP scope. FD tangent is correct, just O(n) more expensive per matvec.
Considered: Skipping the tangent entirely (bad convergence); partial analytical tangent (complex split). FD was simplest correct option. Pointer: "See PLAN-A Phase 8 (analytical tangent)".
D-2 Nightly benchmark failures create issues, not block merges (P4-3)
What: CI nightly e2e tier files a GitHub issue on benchmark failure but does not fail the merge gate.
Why: Benchmark results can vary with numerical noise or platform differences; making them hard blockers caused false CI failures during Sprint 3 development.
Considered: Keeping them as hard blockers. Risk accepted: a genuine regression could slip through, but the issue trail still makes it traceable.
D-3 ScipyCGSolver + analytical elastic tangent — 60–370× speedup
What: Replaced FD tangent with analytical elastic tangent; introduced ScipyCGSolver adapter (commit 6897c3d).
Why: Convergence test wall time was prohibitively slow with FD; the 4-level MMS test and necking bar were unusable at that speed.
Considered: Iterative FD improvement. Decided analytical was worth the implementation cost because three tests could be un-skipped and the speedup applies across all elastic benchmarks.
D-4 Supply-chain date lock: exclude-newer = 2026-02-20
What: pyproject.toml sets exclude-newer = "2026-02-20T00:00:00Z", blocking any package version published after that date from being resolved by uv.
Why: Defense against supply-chain attacks (compromised package releases). Bump this date intentionally after auditing the diff in uv.lock.
Considered: Version pinning without the date gate. Date gate was chosen because it catches newly published malicious versions even of indirect deps with pinned ranges.
D-5 Root-suite pytest over package-by-package invocation (Phase 6 exit criterion)
What: The official verification command is uv run pytest --tb=short -q from the repo root, collecting both packages simultaneously.
Why: A conftest collision between mechdsl-core and algo2code under --import-mode=importlib only surfaced when both packages were collected together. Fixing it at the root level ensures the integration surface is always exercised.
Considered: Package-by-package (faster, avoids conflicts). Decided root-suite is worth the setup cost because the collision was a real bug, not a tooling annoyance.

06 · Mental Model Essentials

The 9 things you need to hold in your head to work on this project effectively.

1
Three explicit IRs, never bypassed
ProblemIR → ElementIR → EinsumIR. Symbolic expressions never call the backend directly. Every layer boundary is a typed, immutable handoff. Skipping a layer is always a bug.
2
Validation at construction, not call-time
All IR dataclasses validate in __post_init__. If a ProblemIR or HexMesh was constructed, its invariants hold. Errors surface at the boundary, not deep inside codegen.
3
Unsupported = raise with Plan B phase reference
Every rejection names which Plan B phase adds that feature (e.g., "Updated Lagrangian is planned for Plan B phase B1"). Callers always know whether to wait or implement.
4
ti.static vs runtime — index partitioning rule
Physics indices (range ≤ 6: spatial i,j,k,l; material I,J,K,L) → ti.static. Mesh indices (nodes, quads, elements) → runtime loops. Never unroll mesh indices — JIT budget explodes.
5
JIT budget hard limits
512 unrolled lines per @ti.func, 2 000 per @ti.kernel, 5 000 absolute ceiling. The einsum optimizer enforces this. Exceeding it causes silent JIT slowdowns, not errors.
6
Voigt ordering: unscaled, not engineering
[xx, yy, zz, xy, xz, yz] with unscaled shear components (tensorial Voigt). Engineering Voigt has factors of 2 on shears — this codebase does not. Mixing them is silent and numerically wrong.
7
Index convention: case encodes domain
Lowercase i,j,k,l = spatial (current config). Uppercase I,J,K,L = material (reference config). Mixed F_{iI} = two-point tensor. Violating this is a physics error.
8
Always uv run — never invoke tools directly
uv run pytest, uv run ruff, uv run mypy. Never bare pytest / python / ruff — they may pick up the wrong environment or not exist on PATH.
9
Design docs win over code
dev/design_docs/ is read-only authority. 07-CONVENTIONS.md always wins over conflicting code or comments. Sign convention: tension-positive stress, compression-positive pressure (p = −m).
07 · Cognitive Debt Hotspots

Areas where understanding is weakest or rationale is most likely to evaporate.

High packages/mechdsl-core/src/mechdsl/codegen/taichi_printer.py · lines 517–520
The J2 plasticity kernel emits a finite-difference consistent tangent as a deliberate fallback. The TODO comment reads: "Replace FD tangent with analytical consistent tangent … O(n) more expensive per matvec. See PLAN-A Phase 8 (analytical tangent)." This function is called from the J2 kernel emission path and affects Newton convergence rate for every plastic solve. The behavior switch (FD vs analytical) is undocumented inline beyond the TODO, and the performance implications are easy to forget.
Suggestion: Add a doc comment at the function head explaining the FD approach, its convergence-rate cost vs analytical, and the Plan B (Phase B analogue) that resolves it. Link to the design doc section. This function will be the first stop in Sprint 4.
Medium packages/mechdsl-core/src/mechdsl/symbolic/ (kinematics, constitutive, voigt)
The symbolic layer (kinematics chain F→C→E→J, constitutive evaluation, Voigt contraction) is exercised through full-pipeline tests and individual unit tests in test_symbolic.py, test_kinematics.py, and test_voigt.py, but there are no dedicated boundary tests at the symbolic-to-IR interface. It's unclear from the test files alone which combinations of symbolic outputs are valid inputs to ProblemIR construction without reading the lowering code.
Suggestion: Add a test module test_symbolic_ir_interface.py that explicitly checks which symbolic outputs produce valid IR and which should raise at the IR boundary. This will matter when Plan B adds new kinematic terms.
Medium packages/mechdsl-core/src/mechdsl/verify/_assembly.py
An explicit ndarray cast was added to the Newton residual closure in Phase 6 as a mypy fix (commit: "Finish sprint 3 phase 6 exit"). The cast is structurally innocuous but there is no test that exercises the code path where the cast matters (i.e., where the input is not already an ndarray). If the upstream type changes in Plan B, this cast could mask a real type error.
Suggestion: Add a test case with a mock array-like input to _assembly.py to verify the cast path is exercised and the residual computation is correct regardless of input container type.
Low packages/algo2code/tests/ (fixture restructure, Phase 6)
The algo2code test suite was restructured in Phase 6 to use fixture-driven sample access instead of direct conftest imports, to resolve the pytest root-suite collection collision. The fixture content (pcg_latex and siblings) is now defined in conftest.py but the intent of each fixture — what algorithm variant it represents and why — is implicit.
Suggestion: Add a one-line docstring to each fixture in packages/algo2code/tests/conftest.py describing the algorithm variant and its key properties. Low effort, high payoff when re-entering this code.
