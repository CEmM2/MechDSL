Walking the contract back to LaTeX

A two-plan recovery: meta-plan that re-shapes the recovery plan, then the recovery plan's own first three phases.

28 commits 132 files changed +9,706 / −158 lines 26 tasks done 14 GH issues closed generated 2026-04-27
01Executive summary

The MechDSL design promised a LaTeX-driven compiler. Execution drift quietly shipped a programmatic-construction build_context() as the public surface. This work re-establishes the LaTeX-first contract — additively, without deleting any of the runtime, codegen, or solver work that was right.

The change ships in three layers, each landing on top of the previous one. back2latex is a meta-plan that reshapes recovery_plan_latex_contract.md so Aut_Faciam can ingest it: canonical task IDs, action-item table columns, Code reality anchors, cross-phase dependency blocks, supersession banners on superseded MVP plans. With those amendments in place, the recovery plan decomposes cleanly into 38 task JSONs.

The recovery plan itself then runs its first two phases end-to-end — Phase 1 (R0) freezes the stable/experimental tier boundary, normalises the four-value tracker vocabulary, marks experimental codegen / dynamics / materials / elements in their own module docstrings, and records the frontend deferral as historical drift, not defect. Phase 2 (R1) introduces mechdsl.compile_latex(source, profile) as the canonical façade, demotes build_context() to a documented secondary API, splits frontend responsibilities (NRPyLaTeX = parser of record; local code = adapter / normalizer / validator) in a new ARCHITECTURE.md, and adds the first test suite that begins from a real LaTeX source string.

Phase 3 (R2) is the first phase that touches a heavily-consumed dataclass — ProblemIR gains four optional semantic enrichment fields (fields, domain, mesh_contract, residual_contract) with their own frozen dataclasses and round-trip serialization. P3-1 is done; P3-2 / P3-3 / P3-4 / P3-5 remain as scaffolded stubs for the next engagement.

04Major shifts (before / after)

The LaTeX entry surface

The single most visible recovery: there is now a public compile_latex that takes a string and returns an ArtifactBundle. The old programmatic path is preserved but framed as secondary.

Before
After

mechdsl/__init__.py exported only compile (re-export from mechdsl.codegen).

To compile a problem you had to:

  • call build_context(...) with typed kwargs
  • hand-translate that dict into a ProblemIR
  • then call compile(problem_ir)

frontend.parse(source) existed but no public façade routed LaTeX through to a bundle. Tests constructed ProblemIR directly from typed enums.

README Quickstart led with build_context. nrpylatex in pyproject.toml, never imported.

compile_latex(source: str, profile: str = "mvp") -> ArtifactBundle is the canonical entry point.

Internally:

  • frontend.parse(source) walks the % mechanics directive set
  • _problem_ir_from_context adapts the dict to a ProblemIR
  • codegen.compile (unchanged) emits Taichi

build_context still works — module + function docstrings now mark it as secondary and point at compile_latex.

README Quickstart leads with the LaTeX example. frontend/ARCHITECTURE.md documents the NRPyLaTeX-as-parser-of-record split.

ProblemIR: from data carrier to semantic centre

Recovery R2 / P3-1 added four optional enrichment fields with their own frozen dataclasses, plus extended to_dict/from_dict to round-trip both legacy and enriched forms. Strict additive change — every existing call site keeps working.

Before
After

ProblemIR carried 10 fields (dim, formulation, element_type, material, boundaries, coord_spatial, coord_material, declared_regions, configuration, dynamics_mode).

Information about what fields the problem solves for, what domain it lives on, what the mesh must provide, and which residual terms are present was implicit — encoded in scattered runtime/codegen logic.

to_dict/from_dict already existed but covered only the original 10 fields.

ProblemIR now carries 14 fields. The new four are optional with safe defaults:

  • fields: tuple[FieldSpec, ...] = ()
  • domain: DomainSpec | None = None
  • mesh_contract: MeshContract | None = None
  • residual_contract: ResidualContract | None = None

to_dict always emits the new keys; from_dict accepts both legacy and enriched dicts. Each enrichment dataclass is independently round-trippable. 325/325 wider regression green.

Governance vocabulary

Recovery R0 / P1-4 promoted the tracker status set from two values to four, and recorded the frontend deferral honestly so future readers don't waste cycles on tasks that were silently substituted.

Before
After

Trackers used only not_started and done. This conflated three genuinely different states:

  • Work never started
  • Work consciously deferred
  • Work substituted by alternate code under a different task ID

The frontend tasks P2.1..P2.5 sat as not_started indefinitely — implying gaps that weren't real (the bypass via build_context already covered them).

Canonical four-value vocabulary defined in dev/tracking/STATUS_LEGEND.md:

  • not_started · in_progress · done
  • deferred · implemented-via-substitute

The five MVP P2.x rows have been retagged implemented-via-substitute with substitute citations. frontend_drift_history.md classifies the deferral as historical drift, not defect, so the planning trail tells the truth.

08Code review

Good

Solid choices · clean patterns
  • Additive-only IR change. P3-1 added 4 fields with safe defaults instead of breaking the 84 ProblemIR(...) call sites. to_dict always emits the new keys; from_dict accepts both shapes. mechanics_ir.py:159–278
  • Round-trip discipline. Each enrichment dataclass has its own to_dict/from_dict + a standalone unit test. The composite test (test_p3_1.py) covers both legacy-no-keys and full-enrichment dicts.
  • Compile-time experimental markers. Tier separation lives in module/class docstrings (mfem_printer.py:1–10, moose_printer.py:1–10, lumped_mass.py:1–8, ElementType docstring) — discoverable without runtime overhead.
  • Frozen dataclasses respected. All four new types are @dataclass(frozen=True); field(default_factory=dict) used instead of bare mutable defaults.
  • Hard-stop invariant retired honestly. The historical test_no_exec_artifacts_present was renamed to test_completion_data_consistent_with_status when its premise expired — original contract preserved in test docstring + back2latex/gates/phase_2_gates.md.
  • Per-task gate transparency. Gate-history files (gates/phase_{1,2,3}_gates.md) record Iron Law evidence — exact pytest commands and pass/total counts — for every task.

Bad

Concrete issues to fix
  • CHANGELOG.md not updated. 28 commits shipped, [Unreleased] section is empty. Public API gained compile_latex + 4 dataclasses; tier policy is now load-bearing for downstream contributors. Should land before merge.
  • One Code reality anchor citation was provably stale before P3-1. The Phase-3 anchor in the recovery plan said "ProblemIR has no to_dict/from_dict" — but they existed at lines 336/353 already. Caught and worked around (the work became "extend" rather than "add from scratch"), but a similar inaccuracy could mislead a future task agent. Worth a P3 retrospective sweep against current code.

Ugly

Tech debt — works now, will bite later
  • Two adapter homes for the same job. mechdsl/__init__.py::_problem_ir_from_context (Phase 2) does the same work that ProblemIR.from_context() would do (Phase 3 / P3-2 territory). The adapter should migrate when P3-2 lands; until then there are two construction paths to keep in sync.
  • Permissive metadata bags. DomainSpec.metadata, MeshContract.metadata, ResidualContract.metadata are dict[str, Any] on a frozen dataclass. frozen=True blocks attribute reassignment but not mutation through the dict. Future schema growth will tempt callers to write into the bag in place.
  • FieldSpec.kind is a bare str. No runtime guard against out-of-vocabulary values like "matrix" or typos. Validation is deferred to P3-5 — explicit decision but currently unenforced.
  • ~70 JSON / markdown tracking files. The Aut_Faciam artifacts are correct and useful, but the sheer volume of dev/tasks/.../json/*.json + tracker + handoff + gate-history files dominates the diff stats. Worth thinking about whether some of this should move to a sidecar branch or be regenerated on demand.
  • Bespoke .context/ Python orchestrators. 8+ scripts in .context/ are gitignored helpers (issue creation, scaffold automation). They worked, but they're not source-controlled and their logic isn't documented for the next agent. Risk: the next session re-derives them poorly.

Questions

Wants reviewer input
  • Should the GitHub-issue-map JSON files live in the repo at all, or under a sidecar mechanism (gitignored + recreated)? They get noisy diffs every time issues are created.
  • The .context/ orchestrator scripts (recursive_plan2tasks.py, recovery_scaffold_phase{1,2,3}.py, etc.) are useful but ungoverned. Should they be promoted into a real scripts/ directory or stay as ephemeral session artifacts?
  • Recovery P3-2 will likely move _problem_ir_from_context onto ProblemIR as a classmethod — happy with that direction or prefer keeping the adapter at the package surface?
  • compile_latex(..., profile="mvp") currently rejects all other profiles with ValueError. Long-term will profile become an enum + registry, or stay a string with allowlist?

10Re-entry context
Note from present-you to future-you

Key invariants

  • All 84 ProblemIR(...) construction sites must continue to work without source-level edits. Every new ProblemIR field must default to a safe empty / None.
  • Each enrichment dataclass (FieldSpec, DomainSpec, MeshContract, ResidualContract) is independently round-trippable via to_dict/from_dict. Adding a field to one means updating both.
  • ProblemIR.to_dict() ALWAYS emits the four enrichment keys, even when their values are empty. Forward consumers can rely on key presence.
  • ProblemIR.from_dict() MUST accept legacy dicts that omit those keys (for golden-file backward compat).
  • compile_latex only accepts profile="mvp". Future profiles must be added with a fail-closed default — never relax this.
  • Tracker rows referencing the deferred/superseded frontend tasks (P2.1..P2.5) must use implemented-via-substitute + a substitute citation. Never silently re-tag them done.

Non-obvious coupling

  • mechdsl/__init__.py::_problem_ir_from_context assumes a stable context-dict shape (10 keys) returned by frontend.build_context. If P3-2 moves the adapter onto ProblemIR, the shape contract follows it.
  • The recovery plan's Phase-3 Code reality anchor ("ProblemIR has no to_dict/from_dict") is now historically inaccurate but intentionally kept in recovery_plan_latex_contract.md for traceability with the original anchor commit. Don't "fix" it unless updating the anchor's date stamp too.
  • frontend/ARCHITECTURE.md talks about NRPyLaTeX as the "parser of record" — but no production code imports nrpylatex yet. The doc is forward-looking; the dependency is wired in pyproject.toml only.
  • Two task namespaces — back2latex and recovery_plan_latex_contract — overlap on P1-6 by design. They live under dev/tasks/<plan>/json/ respectively.
  • The dev/tasks/<plan>/github_issue_map.json file is the source of truth for issue numbers — both scripts/orchestrators and any future gh issue close calls must read it, not re-discover.

Gotchas

  • Existing tests/test_p2_4.py is back2latex-namespaced; recovery_plan_latex_contract/test_p2_4.py is the recovery-namespaced sibling. Same filename, completely different scope. Don't confuse them.
  • The MVP_plan tracker has both a 10-column main task table and a 3-column verification mapping table — both rows start with | P2.. Any tracker scanner needs a column-count discriminator (P2-4 hit this).
  • The _problem_ir_from_context adapter ignores any keys outside the known MVP set. If a Plan B follow-up adds a context key, the adapter silently drops it. Audit at P3-2 time.
  • frozen=True on DomainSpec/MeshContract/ResidualContract doesn't prevent dict-mutation through the metadata bag. Don't rely on it for invariants.
  • The .context/ directory holds session-only orchestrator scripts. Gitignored. Re-running them blindly will regenerate GitHub issues — read first, don't replay.

Don't forget

  • CHANGELOG.md is empty under [Unreleased]. Add an entry summarising compile_latex, ProblemIR enrichment, and the tier policy before merge.
  • Phase 3 has 4 remaining tasks: P3-4 (stable subset, independent), P3-2 (compat constructors), P3-3 (move BC/domain into IR — touches lowering/solver/codegen), P3-5 (IR validation).
  • Recovery Phases 4-7 are still un-scaffolded. Phase 4 (R3) is the next high-blast-radius phase — ElementIR + lowering boundaries.
  • When P3-2 lands, the _problem_ir_from_context adapter at mechdsl/__init__.py:79–141 migrates to ProblemIR.from_context(). compile_latex rewires accordingly.
  • One Code reality anchor was wrong (Phase 3, "no to_dict/from_dict"). Spot-check the others against current code at P3 retrospective time.
