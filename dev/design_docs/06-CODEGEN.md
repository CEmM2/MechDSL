# 06 — Code Generation (Taichi Backend)

**Until v1.0, Taichi is the sole backend.** This document specifies Taichi code generation exclusively. MFEM and MOOSE backends are deferred to Plan B phase B8.

---

## 1  Architecture

### 1.1  Input: Element IR, not SymPDE trees

Code generation consumes **Element IR** (see `05-ELEMENT-IR.md`), not raw SymPDE `TerminalExpr` trees. The Element IR provides:

- Cell type, basis functions, quadrature rule
- Material evaluation contract (inputs, outputs, state variables)
- Local force and tangent expressions with einsum strings
- Contraction plans with tier assignments from the einsum optimiser
- Convected coordinate data (metric tensors)

The printer never inspects SymPy symbolic trees directly. All symbolic information has been lowered to Element IR before code generation begins.

### 1.2  Printer architecture

```python
class TaichiPrinter:
    """Taichi code generator. Consumes Element IR, emits a self-contained .py file."""

    def generate(self, element_ir: ElementIR, problem_ir: ProblemIR) -> str:
        """Return complete Taichi solver source code."""
        sections = [
            self.emit_header(problem_ir),
            self.emit_imports(),
            self.emit_constants(problem_ir),
            self.emit_data_structures(element_ir, problem_ir),
            self.emit_tier1_library(),
            self.emit_constitutive_kernel(element_ir),
            self.emit_element_kernel(element_ir),
            self.emit_tangent_operator(element_ir),
            self.emit_boundary_conditions(problem_ir),
            self.emit_newton_driver(problem_ir),
            self.emit_mesh_io(),
            self.emit_postprocess(),
            self.emit_main(problem_ir),
        ]
        return '\n\n'.join(sections)
```

### 1.3  Artifact capture

The printer records every emission decision in the artifact bundle:

- Which tier was used for each contraction step
- Which library function was called (Tier 1) or which loop nest was emitted (Tier 2)
- Total unrolled line count per `@ti.func` and per `@ti.kernel`
- Budget headroom remaining

## 3  Data structures

### 3.1  Mesh and displacement fields

```python
n_nodes = ti.field(ti.i32, shape=())
n_elems = ti.field(ti.i32, shape=())
coords     = ti.Vector.field(3, dtype=ti.f64, shape=MAX_NODES)       # reference coordinates X
conn       = ti.field(ti.i32, shape=(MAX_ELEMS, 8))                  # hex8 connectivity
u_field    = ti.Vector.field(3, dtype=ti.f64, shape=MAX_NODES)       # displacement
f_int      = ti.Vector.field(3, dtype=ti.f64, shape=MAX_NODES)       # internal forces
f_ext      = ti.Vector.field(3, dtype=ti.f64, shape=MAX_NODES)       # external forces
```

### 3.2  State variables (per quadrature point)

```python
# Current step
stress     = ti.Matrix.field(3, 3, dtype=ti.f64, shape=(MAX_ELEMS, 8))  # Cauchy or PK2
peeq       = ti.field(ti.f64, shape=(MAX_ELEMS, 8))                     # equivalent plastic strain

# Previous step (copied at end of converged load step)
stress_old = ti.Matrix.field(3, 3, dtype=ti.f64, shape=(MAX_ELEMS, 8))
peeq_old   = ti.field(ti.f64, shape=(MAX_ELEMS, 8))
```

### 3.3  Element stiffness storage

**Do not** store full element stiffness matrices as `ti.Matrix` fields. For Hex8, the element stiffness is 24×24 = 576 entries — this triggers Taichi unrolling warnings and wastes memory. Instead:

- Use **matrix-free** tangent application: compute $y = K(\mathbf{u})\,x$ on-the-fly per element.
- Store only the constitutive tangent (6×6 Voigt) at each quadrature point if needed for reuse.

### 3.4  Convected coordinate data

```python
# Reference metric G_IJ (precomputed from mesh, constant for Cartesian reference)
ref_metric = ti.Matrix.field(3, 3, dtype=ti.f64, shape=(MAX_ELEMS, 8))

# Current metric g_IJ = C_IJ (recomputed every Newton iteration)
cur_metric = ti.Matrix.field(3, 3, dtype=ti.f64, shape=(MAX_ELEMS, 8))
```

For the MVP (Cartesian reference configuration), `ref_metric` is the identity at all quadrature points. The infrastructure is in place for curvilinear meshes in Plan B.

## 4  Constitutive kernel

### 4.1  Generated function

The constitutive kernel is a `@ti.func` that evaluates stress and tangent at **one quadrature point**. Its body is generated from the symbolic expressions in Element IR.

```python
@ti.func
def constitutive_update(F: ti.types.matrix(3, 3, ti.f64),
                        peeq_old_q: ti.f64,
                        stress_old_q: ti.types.matrix(3, 3, ti.f64),
                        dt: ti.f64
) -> tuple[ti.types.matrix(3, 3, ti.f64),   # PK2 stress S
           ti.types.matrix(6, 6, ti.f64),   # Voigt tangent C_alg
           ti.f64]:                           # updated peeq
    # ── Kinematics ──
    C = F.transpose() @ F       # Tier 1: right Cauchy-Green
    E = 0.5 * (C - ti.Matrix.identity(ti.f64, 3))  # Green-Lagrange strain
    J = F.determinant()

    # ── Elastic predictor (St. Venant-Kirchhoff) ──
    # S_trial = C_IJKL * E_KL  (generated from symbolic, Tier 2 or Voigt)
    ...

    # ── Yield check ──
    # σ_eq, yield function f
    ...

    # ── Return mapping (radial return, power-law hardening) ──
    # if f > 0: scalar Newton for Δλ
    ...

    # ── Algorithmic tangent ──
    # C_alg in Voigt (elastic or consistent elasto-plastic)
    ...

    return S, C_alg_voigt, peeq_new
```

### 4.2  Expression emission

The symbolic expressions for stress and tangent are emitted using **CSE** (common subexpression elimination) from SymPy:

```python
from sympy import cse
replacements, reduced = cse(tangent_expressions)
# Emit replacements as Taichi local variables
# Emit reduced expressions as the final computation
```

CSE typically reduces operation count by 30–60% for complex tangent expressions.

### 4.3  Numerical safeguards

Generated constitutive code includes:

| Check | Guard | Tolerance |
|-------|-------|-----------|
| Element inversion | $J > 0$ | $J > 10^{-15}$ |
| F invertibility | $\det(F) > \text{tol}$ | $10^{-15}$ |
| Flow direction | $\sigma_{eq} > \text{tol}$ before $n = s / \|s\|$ | $10^{-12}\,\sigma_y$ |
| Plastic multiplier | $\Delta\lambda \ge 0$ | $\ge -10^{-15}$ |

See `07-CONVENTIONS.md §6` for the full tolerance table.

## 5  Element kernel

### 5.1  Internal force kernel

```python
@ti.kernel
def compute_internal_forces():
    for e in range(n_elems[None]):
        for q in ti.static(range(8)):           # 2×2×2 Gauss
            # 1. Build deformation gradient from shape grads and displacements
            F = build_F(e, q)                    # Tier 1 accumulation

            # 2. Constitutive update (stress + tangent + state)
            S, C_alg, peeq_new = constitutive_update(
                F, peeq_old[e, q], stress_old[e, q], dt)

            # 3. PK1 from PK2
            P = F @ S                            # Tier 1: pk1_from_pk2

            # 4. Scatter to nodal internal forces
            for a in range(8):                   # runtime loop over nodes
                dN_dX = shape_grad_phys[e, q, a] # precomputed or on-the-fly
                force_contrib = P @ dN_dX * det_J[e, q] * w_q[q]
                ti.atomic_add(f_int[conn[e, a]], force_contrib)

            # 5. Store updated state
            stress[e, q] = S
            peeq[e, q] = peeq_new
```

**Budget:** Physics kernel (36 + 6 static lines) + scatter (81 static lines) = 123 total. Well within the 2000-line kernel budget.

### 5.2  Deformation gradient computation

```python
@ti.func
def build_F(e: int, q: int) -> ti.types.matrix(3, 3, ti.f64):
    F = ti.Matrix.identity(ti.f64, 3)
    for a in range(8):                           # runtime: 8 nodes
        for i in ti.static(range(3)):            # static: spatial
            for I in ti.static(range(3)):        # static: material
                F[i, I] += u_field[conn[e, a]][i] * dN_dX[e, q, a, I]
    return F
```

### 5.3  Shape function gradients

Reference-element shape function gradients and quadrature weights are stored as compile-time constants:

```python
# Hex8 trilinear shape functions
# N_a(xi, eta, zeta) = (1/8)(1 + xi_a*xi)(1 + eta_a*eta)(1 + zeta_a*zeta)
# dN_a/d(xi_j) — 8 nodes × 3 parametric coords, stored as flat array
# 2×2×2 Gauss points: xi = ±1/√3, weights = 1.0

# Physical gradients precomputed per element per quad point:
# dN_a/dX_I = dN_a/d(xi_j) * J^{-1}_{jI}
dN_dX = ti.field(ti.f64, shape=(MAX_ELEMS, 8, 8, 3))  # [elem, quad, node, dim]
det_J = ti.field(ti.f64, shape=(MAX_ELEMS, 8))          # [elem, quad]
```

### 5.4  Performance considerations

**Atomics:** Internal force scatter uses `ti.atomic_add`. For large meshes, element colouring can avoid atomics — this is a Plan B optimisation.

**Block size:** Use `ti.loop_config(block_dim=128)` for the element kernel.

**Shape gradient precomputation:** Precompute physical gradients and store per element/quad. This costs memory but eliminates redundant Jacobian inversions during Newton iterations.

## 6  Tangent operator (matrix-free)

### 6.1  Matvec function

For the Newton linear solve, the tangent operator is applied matrix-free:

```python
@ti.func
def apply_tangent_element(e: int, q: int, x_local):
    """Compute delta_P from delta_F via constitutive tangent."""
    # 1. Virtual deformation gradient
    delta_F = compute_delta_F(e, q, x_local)

    # 2. Push-forward: delta_P_iI = A_iIjJ * delta_F_jJ
    #    where A_iIjJ = delta_ij S_IJ + F_iK C_KILJ F_jL
    #    Emitted as Tier 2: 243 + 243 = 486 static lines
    delta_P = push_forward_tangent(delta_F, F, S, C_mat)

    # 3. Scatter delta_P · dN to output
    ...

@ti.kernel
def tangent_matvec(x: ti.template(), y: ti.template()):
    """y = K(u) * x, matrix-free."""
    for e in range(n_elems[None]):
        # gather x_local for this element
        ...
        for q in ti.static(range(8)):
            apply_tangent_element(e, q, x_local)
    # Apply Dirichlet: y[fixed] = x[fixed]
    apply_dirichlet_matvec(x, y)
```

### 6.2  Budget for tangent push-forward

The TL push-forward is the most expensive contraction in the system:

| Step | Einsum | Static lines |
|------|--------|-------------|
| $T_{iIjJ} = F_{iK}\,\mathbb{C}_{KILJ}$ | `iK,KILJ->iILJ` | 243 |
| $A_{iIjJ} = T_{iILJ}\,F_{jL}$ | `iILJ,jL->iIjJ` | 243 |
| **Total** | | **486** |

This is Tier 2 (within the 512-line `@ti.func` budget). The full tangent kernel (physics + scatter) stays under 600 static lines — well within the 2000-line kernel budget.

## 7  Einsum-driven kernel emission

### 7.1  Emission workflow

Before emitting any element kernel, the printer:

1. Reads the `ContractionPlan` from the Element IR artifact.
2. For each step in the plan:
   - **Tier 1:** Emits a call to a pre-written library `@ti.func` (e.g. `pk1_from_pk2(F, S)` → `F @ S`).
   - **Tier 2:** Emits an inline `ti.static` loop nest. The emitter walks the step's einsum string and generates index arithmetic, intermediate allocation, and accumulation.
   - **Tier 3:** Emits runtime loops for outer indices, `ti.static` for the innermost contracted dimension only.
3. Validates the total unrolled line count against the JIT budget.
4. If budget exceeded, restructures into multiple `@ti.func` sub-functions.

### 7.2  Tier 1 library functions

Pre-written and tested, not generated:

```python
@ti.func
def mat_mul_33(A, B): return A @ B

@ti.func
def mat_mul_T_33(A, B): return A.transpose() @ B

@ti.func
def pk1_from_pk2(F, S): return F @ S

@ti.func
def cauchy_from_pk1(P, F, J): return (1.0 / J) * (P @ F.transpose())

@ti.func
def right_cauchy_green(F): return F.transpose() @ F

@ti.func
def det_33(F): return F.determinant()

@ti.func
def inv_33(F): return F.inverse()
```

### 7.3  Tier 2 emission example

For the push-forward step `iK,KILJ->iILJ` (3D):

```python
# Generated ti.static loop nest
T = ti.Matrix.zero(ti.f64, 3, 3, 3, 3)  # or flat local storage
for i in ti.static(range(3)):
    for I in ti.static(range(3)):
        for L in ti.static(range(3)):
            for J in ti.static(range(3)):
                val = 0.0
                for K in ti.static(range(3)):
                    val += F[i, K] * C_mat[K, I, L, J]
                T[i, I, L, J] = val
```

This produces exactly 243 multiply-add statements when unrolled.

## 8  Convected coordinate support

### 8.1  MVP: Cartesian reference

For the MVP, the reference configuration uses Cartesian coordinates. This means:

- Reference metric $G_{IJ} = \delta_{IJ}$
- Christoffel symbols $\Gamma^K_{IJ} = 0$
- Covariant derivative reduces to partial derivative

The convected framework is **architecturally present** but **numerically trivial** in the MVP. The infrastructure (metric field storage, convected-aware kinematics) is built so that Plan B phase B2 can extend to curvilinear reference configurations without restructuring.

### 8.2  Kinematics in convected form

Even with Cartesian reference, the kinematics are expressed in convected notation:

```python
@ti.func
def compute_convected_kinematics(F):
    # Current metric g_IJ = C_IJ = F^T F
    g = F.transpose() @ F        # = C (convected metric)
    # Green-Lagrange strain E_IJ = 0.5 * (g_IJ - G_IJ)
    E = 0.5 * (g - G_ref)        # G_ref = I for Cartesian
    return g, E
```

### 8.3  Plan B extension points

| Extension | What changes |
|-----------|-------------|
| Curvilinear reference mesh | $G_{IJ} \ne \delta_{IJ}$, precomputed from mesh |
| Christoffel symbols | $\Gamma^K_{IJ} \ne 0$, needed for covariant derivatives |
| Metric update per iteration | $g_{IJ}$ recomputed from current deformation |

## 9  Solver scaffolding

### 9.1  Newton-Raphson driver

```python
def newton_solve(u, f_ext, tol=1e-8, max_iter=20):
    for iteration in range(max_iter):
        f_int = compute_internal_forces(u)
        R = f_int - f_ext
        apply_dirichlet_residual(R)
        r_norm = norm(R)
        if r_norm < tol * r_norm_0:
            return u, iteration

        # Linear solve: K du = -R using imported solver
        matvec = lambda x: tangent_matvec(u, x)
        du = linear_solver.solve(matvec, -R)
        apply_dirichlet_increment(du)
        u += du
```

### 9.2  Load stepping

Incremental loading with adaptive step size:

- If Newton converges in < 5 iterations: increase step size (×1.5)
- If Newton fails to converge: halve step size and retry
- History variable copy (`stress → stress_old`, `peeq → peeq_old`) only at converged steps

### 9.3  Imported linear solver interface

- Load parameter $\lambda$
- Residual norm $\|R\|$

## 11  Future backends (Plan B phase B8)

The MFEM and MOOSE backends will be added after v1.0. They consume the same Element IR and contraction plans but emit C++ instead of Python/Taichi. Key considerations preserved in the architecture:

- **MFEM:** Generates `NonlinearFormIntegrator` subclass. Must convert tensorial Voigt → MFEM's engineering Voigt at the interface. Supports MPI parallelism natively.
- **MOOSE:** Generates `ComputeStressBase` subclass. Uses `RankTwoTensor`/`RankFourTensor` with its own ordering. Material system handles history variables via `_old` properties.

The IR-based architecture ensures these backends can be added without modifying the symbolic engine, Mechanics IR, or Element IR. Only new printer classes are needed.
